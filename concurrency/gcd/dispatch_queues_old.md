# Очереди диспетчеризации
Очередь диспетчеризации - это структура, которая управляет отправленными в неё задачами. 
Задачи, отправленные в очередь, исполняются в FIFO порядке.
GCD предоставляет главную очередь и несколько глобальных конкурентных, можно создавать свои.
### Преимущества очередей перед потоками
- Не нужно писать код для управления потоками, система сама занимается этим, справляясь эффективнее.
- Система может динамически масштабировать количество потоков в зависимости от доступных ресурсов и текущих системных условий.
- Система обычно начинает выполнение задачи быстрее, чем при ручном создании потока.
- Синхронизация доступа к ресурсу последовательной очередью эффективнее так как не требует вызова ядра.
- Очереди не блокируют используемые потоки.
### Несколько ключевых моментов
- Очереди выполняют свои задачи параллельно по отношению к другим очередям. Сериализация задач работает только внутри очереди.
- Система определяет общее количество задач, выполняемых в любой момент времени. Таким образом, приложение со 100 задачами в 100 различных очередях не может выполнять все эти задачи одновременно (если оно не имеет 100 или более эффективных ядер).
- Система учитывает уровни приоритета очереди при выборе новых задач для начала.
- Задачи в очереди должны быть готовы к выполнению в момент их добавления в очередь.
- Созданные вручную очереди - это ссылочные объекты.
## Последовательные и конкурентные очереди
Очереди есть двух типов: последовательные и конкурентные.

Последовательные выполняют задачи по одной в порядке FIFO.
Конкурентные так же выполняют задачи в порядке FIFO, но могут начать выполнение следующих задач до завершения уже запущенных.

Количество задач одновременно выполняемых очередью, зависит от многих факторов
- Остальные процессорные ресурсы заняты другой работой
- Другие задачи этой очереди ещё не готовы к выполнению
- Другие задачи ждут блокировку
- Выполнение ограничено семафором
- Сейчас выполняется барьерная задача
- Для данной очереди в данный момент времени доступен только один поток
- На планирование влияют приоритет, текущая нагрузка, энергосбережение и температурные ограничения

> [!IMPORTANT]
> Таким образом, конкурентная очередь вообще не гарантирует параллельное выполнение задач.

### Очереди, предоставляемые GCD
GCD предоставляет 
- главную последовательную очередь `DispatchQueue.main`
- несколько глобальных конкурентных очередей `DispatchQueue.global(qos:)`, отличающихся качеством обслуживания (Quality of Service).
### Создание своих очередей
Создание своих последовательных очередей оправдано в случае, если нужно защитить общие ресурсы или изменяемые структуры путем сериализации доступа к ним.  
Можно создавать неограниченное количество последовательных очередей, но Apple прямо предупреждает, что не стоит плодить последовательные очереди ради 
одновременного исполнения задач, рекомендуется отправлять их в одну из глобальных очередей.  
Кроме того, Apple рекомендует обосновывать для себя необходимость при создании очередей, например защиты ресурса или синхронизации ключевого поведения.
## Качество обслуживания (QoS)
[Качество обслуживания](https://developer.apple.com/documentation/dispatch/dispatchqos) (приоритет выполнения) указывает на важность выполнения задачи для приложения.  
При планировании задач система отдает приоритет задачам с более высоким качеством обслуживания.

Работа с более высоким приоритетом выполняется быстрее и с большим количеством ресурсов:
- Чаще получает процессорное время
- Система может предпочитать более производительные ядра для выполнения
- Система может заставлять процессор работать в более производительном режиме
Но она, как правило требует больше энергии, чем работа с низким приоритетом.

> [!IMPORTANT]
> Точное указание соответствующего работе QoS важно для отзывчивости и энергоэффективности приложения.
