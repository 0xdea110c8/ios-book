## Dispatch
### Описание
`Dispatch framework` позволять планировать блоки на асинхронное и конкурентное выполнение методами, описанными в [DispatchQueue.async](#dispatch_async)
и dispatch_apply.  
`Dispatch queues` - это базовые юниты организации блоков. Несколько очередей создаются по умолчанию, приложения могут создавать
дополнительные (см. dispatch_queue_create).   
`Dispatch groups` позволяют приложениям отслеживать прогресс выполнения блоков, отправленных в очереди, и совершать действия 
по завершении выполнения блоков (см. dispatch_group_create).  
`Dispatch framework` так же предоставляет методы для отслеживания системных событий и автоматической отправки обработчиков событий
в dispatch queues.

## DispatchQueue.async
### Описание
Методы `DispatchQueue.async(group:qos:flags:execute:)` и `DispatchQueue.sync(group:qos:flags:execute:)` планируют блоки для конкурентного выполнения 
в фреймворке [dispatch](#dispatch). Блоки отправляются в очередь, определяющую политику их выполнения.
(см. dispatch_queue_create).  
Эти методы поддерживают эффективные временные блокировки, фоновое параллельное выполнение и
параллельное выполнение на уровне данных. Эти же методы могут быть использованы для эффективного уведомления о завершении асинхронных блоков (aka коллбэки).
### Временная синхронизация
Синхронизация часто требуется когда несколько потоков выполнения получают конкурентный доступ к общим данным. Простейшая форма синхронизации - взаимное исключение (блокировка), при
этом различные подсистемы выполняются конкурентно до момента входа в критичную секцию.  
В семействе `pthread` временная блокировка достигается так:
```
int r = pthread_mutex_lock(&my_lock);
assert(r == 0);

// critical section

r = pthread_mutex_unlock(&my_lock);
assert(r == 0);
```
Метод `DispatchQueue.sync(group:qos:flags:execute:)` может быть использован вместе с последовательной очередью для 
достижения того же стиля синхронизации, например:
```swift
myQueue.sync {
     // critical section
}
```
Помимо более лаконичного выражения синхронизации, этот подход менее подвержен ошибкам,
поскольку критичная секция не может быть случайно покинута без возвращения в состояние,
допускающее повторный вход. Отложенная критичная секция имеет те же свойства синхронизации как и код выше, но является неблокирующей и поэтому более эффективной в 
выполнении, например:
```swift
myQueue.async {
     // critical section
}
```
### Фоновое параллельное выполнение
Метод / `DispatchQueue.global(qos:).async(group:qos:flags:execute:)` может быть использован для выполнения простых фоновых задач на глобальной конкурентной очереди, например:
```swift
DispatchQueue.global(qos: .default).async {
     // background operation
}
```
Этот подход является эффективной заменой `pthread_create`.
### Коллбэки по завершении
Коллбэки по завершении могут быть реализованы посредством вложенных вызовов в метод `DispatchQueue.async(group:qos:flags:execute:)`.  
В ARC при работе с пользовательской очередью необходимо обеспечить сильную ссылку на неё на протяжении всего времени, пока она нужна. 
```swift
func executeOnQueue(
    block: @escaping @Sendable () -> (),
    completion: @escaping @Sendable () -> (),
    destinationQueue: DispatchQueue
) {
    myQueue.async {
        block()
        destinationQueue.async {
            completion()
        }
    }
}
```
